An AI assistant in your Obsidian sidebar that asks before it writes.

OWLA Butler runs on the Codex, OpenCode, Claude Code or Hermes Agent CLI you already have signed in. No extra API key, no OWLA account. Every edit it proposes is staged with a diff and waits for your Accept or Decline.

Install from Obsidian Community plugins Download from GitHub

Free and MIT licensed. Needs desktop Obsidian 1.14.5+ and one of the four CLIs; your provider's usage may cost money.

What it does

Chat with the note you have open

OWLA reads the note you are looking at, including unsaved text and your selection, plus a short summary of its properties, outline and links. Name another note or use Add note to bring more in.

Review every edit

Proposed changes are applied provisionally and shown in the editor: removed lines in red, added lines in green. Accept keeps them, Decline restores the previous snapshot, View diff shows the exact Markdown. Moves, renames and deletions go through the same review.

Attach images, PDFs and documents

Paste a screenshot, drop files or use Attach. Whole PDFs, single PDF pages, Office and OpenDocument files are prepared locally; the assistant reads what it needs.

Search your vault, with sources

The assistant can search allowed notes and cite exact paths. The search runs locally at the moment you ask; there is no background index and no vault upload.

Choose the model and effort

The model and reasoning effort sit beside the composer. The list comes from the provider you use, not a fixed menu. On macOS, Automatic model and reasoning effort can pick both for each message instead.

Slash commands

Type / for ready-made requests such as /summarize, /format, /mermaid and /math, plus quick actions like /new and /undo. Keep typing to filter; nothing is sent until you press Send.

Pick your provider

Settings have a tab per provider. Choose a primary provider and an optional fallback for when one reaches its usage limit; OWLA switches back when the limit resets.

How it works

What happens each time you press Send.

  1. 1

    Send

    You write a message, optionally with attachments.

  2. 2

    Context

    OWLA collects the open note (with unsaved text and selection), its summary, your attachments and the last exchanges of this chat. Nothing else.

  3. 3

    OWLA tools only

    The CLI starts in a private working directory. It reads, searches and proposes changes only through OWLA's tools: no shell, no paths outside the vault, no credentials.

  4. 4

    Answer streams

    Text appears as it is written. Proposed edits are applied provisionally and wait for Accept or Decline.

  5. 5

    Process stops

    OWLA reads the reported usage limits and stops the process. The chat context is kept for the next message.

Why OWLA Butler

Uses the AI you already have

Reuses your existing Codex, OpenCode, Claude Code or Hermes Agent login, models and plan limits. No separate API key or OWLA subscription.

Review before write

Edits, moves, renames and deletions are staged for approval, with diffs and recovery snapshots.

No index, no upload

Notes are read when you send a message. No background index of your vault, no whole-vault upload.

Same flow on four providers

Switch providers without learning a new interface. The tools, bundled Obsidian skills and review flow stay the same.

Privacy and data protection

This is a cloud-backed assistant. When you send a message, your current note snapshot (including unsaved text), selections, images, attachment references and recent chat go to the provider you selected, and are processed under that provider's terms. The assistant can then request allowed note text, document excerpts and PDF pages. Web search is on by default and its queries can include that context; you can turn it off in settings.

What OWLA does not do

  • No telemetry or advertising requests. For Codex, OWLA disables analytics, feedback uploads and OpenTelemetry exporters for its own process and checks them before each conversation.
  • No shell and no native file access for the assistant on any provider. It reaches the vault only through OWLA's tools.
  • No background index, no background polling, no whole-vault upload.
  • Does not read or copy your provider credentials, and does not install or update any CLI.
  • Your own CLI plugins, MCP servers, skills and global agent instructions are not loaded into OWLA sessions.

What protects your vault

  • Vault containment: hidden and configuration files, traversal, symlinks escaping the vault and Windows device names such as NUL are refused.
  • Excluded folders you choose are never read, searched or summarised.
  • Every change is proposed for review, never written directly.
  • A private recovery snapshot is stored before each write (up to 20 entries within 5 MB per vault). Decline and Undo check the note still matches before restoring.
  • Saved chats, review records and snapshots live outside the vault, in OWLA's own folder on your computer.

Details: README, “Privacy, network access and files outside the vault” and SECURITY.md.

Requirements and install

You need

  • Desktop Obsidian 1.14.5 or newer on macOS or Windows. Linux and mobile are not supported yet.
  • One provider CLI, installed and signed in: Codex 0.162.1+, OpenCode 2.2+, Claude Code 2.1.322+ or Hermes Agent.
  • An internet connection for answers, sign-in and model discovery.

Cost

OWLA Butler is free. Your provider may charge for its models or usage, depending on your plan: OpenAI may require a paid plan or credits, OpenCode may serve free models and charge for providers you connect, and Anthropic applies your Claude plan's limits. There is no OWLA subscription.

Install

  1. Install a provider CLI and sign in. If it works in your terminal, OWLA can use it.
  2. In Obsidian, open Settings → Community plugins, search for OWLA Butler, install and enable it. Or copy main.js, manifest.json and styles.css from the latest release into <vault>/.obsidian/plugins/owla-butler/.
  3. Open Settings → OWLA Butler and choose your provider. For Codex and Hermes, choose Connect once per vault.
  4. Open the bird icon in the sidebar and send a message.

FAQ

Do I need an API key?

No. OWLA uses the login of the CLI you already have. It removes ANTHROPIC_API_KEY and similar variables from the Claude Code process so replies always use your Claude login.

Does it work offline or with local models?

No. Answers come from your provider's service, so you need an internet connection. OWLA does not run Ollama or downloaded models. (OpenCode and Hermes Agent can route to the providers you connected in them.)

Can it change my notes without asking?

No. Every note change, move, rename or deletion is proposed and waits for Accept or Decline. Decline restores the snapshot taken before the change.

Is my whole vault sent to the AI?

No. The open note, your attachments and recent chat are sent with each message; the assistant can then ask for other allowed notes through OWLA's tools. Excluded folders are never available.

Does it run in the background?

Only while you type and while a reply is running. The process stops 20 seconds after you stop typing and after every reply. Nothing polls in the background.

Why not Linux or mobile?

Both are not supported yet. The plugin is desktop-only and built for macOS and Windows.

Where do I report a bug?

Open an issue on GitHub. Remove note content and personal paths before posting logs.
