# Handoff 5 (wave 2) — Export a note to PDF with pre-export layout fixes

Start only after handoff 4 reports done (shared `src/main.ts`). Run `git status` first.

Proposal item: "Give OWLA the ability to export documents as PDFs using Obsidian built-in tools + is able to make changes to the export before, to fix stuff like title overlapping or being badly placed. Example: title is on page 1, while text is on page 2, even though title could have been on page 2."

## Required work
1. **Feasibility first (write findings into the Report before coding).** Determine what Obsidian's public API offers: the core "Export to PDF" command (`app.commands.executeCommandById('workspace:export-pdf')`), its dialog options (page size, margins, landscape, downscale, open after export), and whether a programmatic export without the dialog is possible on desktop (Electron `webContents.printToPDF` via `window.require('electron')` — check how `src/electron.d.ts`/existing code accesses Electron and whether it is allowed under `AGENTS.md`/community-plugin rules and the OWLA vault guard). Pick the approach that uses Obsidian's own rendering pipeline; if only the dialog route is public, implement "prepare, then open the export dialog for the user to confirm" and say that honestly. Desktop only; mobile must hide the feature.
2. **Export tool.** `export_pdf {path, options?, reason}`. Always requires explicit user confirmation in the UI (it writes a file) and respects allowed-path/excluded-folder rules for both source and output location (default: next to the note, never overwrite silently — name collision → suffix).
3. **Layout fix pass.** Before exporting, OWLA can inspect and fix print layout problems by staging normal note edits through the existing diff system (user accepts/declines): orphan headings (heading last on a page, content next page), title alone on a page, tables/images splitting badly, overlapping title/frontmatter. Mechanism: insert/remove page-break markers (`<div style="page-break-before: always"></div>` / `break-inside: avoid` wrappers) or reorder trivial spacing; never change prose. Pure helpers in new `src/pdf-export.ts`: detect candidate problems from heading/block structure plus page-height estimate (document the heuristic honestly; real pagination is only known after render — if the export pipeline lets you render and measure pages, use that and prefer it).
4. **Verification loop.** After export, read the PDF back with the existing PDF tools (`readPdfTextRange`, page render) to check headings are not stranded, and report findings to the model/user. Cap iterations (max 2 fix rounds).
5. **Skill text.** Add a short `owla-pdf-export` section to the existing `assets/skills/owla-pdf` (or new skill; follow how handoff 2 registers skills — read its report). Tool wiring across providers as in handoff 4.

#### Feasibility findings (verified by reading Obsidian's shipped bundles read-only: `/Applications/Obsidian.app/Contents/Resources/obsidian.asar` (installer) and `~/Library/Application Support/obsidian/obsidian-1.15.1.asar` (the running update); not in the public `obsidian.d.ts` 1.14.4, which has no PDF-export API at all)
- Command `workspace:export-pdf` is registered only when `Platform.canExportPdf`; its callback is `MarkdownView.printToPdf()` on the active Markdown view, which just does `new <PrintModal>(app, file).open()`.
- The modal offers: include file name (as an H1), page size A3/A4/A5/Legal/Letter/Tabloid, landscape, margin (default "0" / none "1" / minimal "2"), downscale 10–100 %. Settings persist in vault config `pdfExportSettings`. There is no "open after export" toggle in the UI; the code always sets `open:true`.
- On confirm it shows an OS save dialog (`remote.dialog.showSaveDialog`, `showOverwriteConfirmation`), then calls the modal's own `printToPdf(options)` → `printToPdfDesktop`: opens a hidden popup window, copies the app's CSS, renders the note with `MarkdownRenderer`-equivalent + post-processors (forced light theme, internal links' `href` removed), then `ipcRenderer.send('print-to-pdf', options)`; the main process runs `webContents.printToPDF(options)` on that popup and writes `options.filepath` itself. The options shape is mirrored exactly by `obsidianPrintOptions()`.
- So a programmatic export **without the dialog is possible only through undocumented internals**. Two routes:
  - **A (public command, dialog):** open/activate the note, `app.commands.executeCommandById('workspace:export-pdf')`. User confirms settings and picks the path in the OS dialog. Honest limits: OWLA cannot set the output path, so allowed-path/collision rules cannot be enforced and the verification loop only works if the user saves inside the vault (detect via `vault.on('create')` for a new `.pdf`).
  - **B (Obsidian's own exporter, no dialog):** obtain the print-modal instance without opening it (call `view.printToPdf()` while `Modal.prototype.open` is replaced by a one-shot capture for that synchronous call), duck-type check `typeof m.printToPdf==='function' && m.file===file`, then `await m.printToPdf(obsidianPrintOptions(opts, adapter.getFullPath(outPath)))`. Same rendering pipeline, OWLA's own confirmation UI, exact output path → collision suffix + read-back verification work. Risk: breaks if Obsidian renames internals; detect and fall back to A. Precedent for internals: `src/visual.ts:108` already uses `electron.remote.getCurrentWebContents()`.
  - **Recommendation:** B with automatic fallback to A, both behind an explicit user confirmation. **Needs the lead's/user's sign-off** because it leans on internals (Community review may question the scoped `Modal.prototype.open` capture). Route C (own `BrowserWindow`/`printToPDF`) rejected: duplicates rendering and loses Obsidian's CSS/post-processors.
- Desktop only: `manifest.json` already has `isDesktopOnly: true`; still gate the tool on `Platform.isDesktopApp` and the command existing (`app.commands.findCommand('workspace:export-pdf')`).
- Page-break markers: Obsidian keeps a raw `<div …>` HTML block (with `style`/`class`) in reading/print rendering, so `<div class="owla-page-break" style="page-break-before: always"></div>` works. **`break-inside: avoid` wrappers around tables/images are not feasible in Markdown**: Obsidian does not render Markdown inside an HTML block, so wrapping a table in a `<div>` would break it. Instead the fix is a page break before the table (and its heading run). A global alternative would be a print CSS rule (`.print h1…h6{break-after:avoid}`, `table,img{break-inside:avoid}`) in `styles.css`; that changes every export and is outside this handoff's files — flagged for the lead.
- Real pagination is only known after render. Measuring pages before export would mean re-implementing the hidden-popup render; not done. Instead: cheap estimate before export (`detectLayoutIssues`), then the **authoritative check reads the exported PDF back** (`pdfLayoutIssues` on `pdfPageText` per page via the existing `loadPdfJs`/`withPdfDocument` path) and maps findings to note lines (`issuesFromPdf`) for at most `PDF_FIX_ROUNDS`=2 fix rounds.

#### `src/pdf-export.ts` (pure, no Obsidian/Electron imports)
- `pdfExportOptions(input, savedPdfExportSettings?)` — validates model input; falls back to the vault's saved `pdfExportSettings`. `obsidianPrintOptions(opts, filepath)` — Obsidian's exact option object.
- `pdfOutputPath(notePath, exists, requested?)` — next to the note, `Note.pdf` → `Note 1.pdf` → `Note 2.pdf` (Obsidian's own suffix style), rejects `..`/`.`/empty; never returns an existing path. Caller must still run the allowed-path/excluded-folder check on the result.
- `markdownBlocks` (frontmatter, headings, paragraphs, lists, quotes, tables, code fences, `$$` math, image embeds, rules, page breaks; fences/math opaque, CRLF-safe).
- Heuristic (documented in the file): `pageGeometry` from paper size in CSS px at 96 dpi, Chromium default margin ≈0.4 in, 16 px × 1.5 line, 8 px glyph, downscale applied; `blockLines` per block kind (headings 1.3–2.6 lines, tables 1.6/row, images from `|WxH` or ~300 px); `estimateLayout` moves headings/images/math whole, lets text/lists/tables/code split.
- `detectLayoutIssues` → `orphan-heading` (heading run with < 2 lines of content after it on the page, or content on the next page), `title-alone` (first heading run, or the include-name title above an image that doesn't fit — **no Markdown fix**, reported only), `split-table`/`split-code` (fits on one page but splits). `fixLine` = before the whole heading run; undefined when the run already starts a page or starts the note.
- `insertPageBreaks` / `removePageBreaks` / `applyLayoutFixes` — idempotent, skip line 0, frontmatter, code/math, and lines already preceded by any page-break div (ours or hand-written); removal deletes only OWLA's marker; exact round trip; keeps CRLF. Never changes prose. Changes are meant to be staged through the normal `propose_edit` diff (user accepts/declines).
- `pdfLayoutIssues(pageTexts, headings, title?)` / `issuesFromPdf` / `layoutReport` — read-back verification.
